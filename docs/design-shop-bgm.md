# 판다 탐험대 설계 메모: 코인 상점 · 판다 꾸미기 · 지역별 배경음악

> **2026-11-12: 1단계 판다 옷장이 게임에 들어갔어요** (아래 0장). 판다 방 꾸미기는 아직 설계만 있어요(아래 5장).
> 아래 1~3장은 예전 설계 메모예요. 실제 구현은 0장을 기준으로 봐 주세요.
>
> (예전 메모) 코인 상점·꾸미기는 **설계만** 있어요. 지역별 배경음악(4장)은 2026-10 게임에 들어갔어요(설정의 배경음악 켜기/끄기 포함, 음량 슬라이더는 아직 없음).
> 중간보스 처치 보너스로 지역마다 동전이 5개 더 생겼어요(처음 한 번만). 그래서 첫 탐험 기준 지역당 약 93개, 세 지역 약 279개예요.

## 0. 판다 옷장 (실제 구현, 2026-11-12)

- 홈 화면 맨 위 줄의 **🐼 판다 옷장** 버튼 → 옷장 창 (`openWardrobe` / `closeWardrobe`, mode `'shop'`)
- 아이템 목록 `SHOP_ITEMS` (src/game.html): `{ id, kind: 'wear', slot, name, price }`

| ID | 이름 | 부위 | 가격 |
|---|---|---|---|
| `w_ribbon` | 빨간 리본 | 머리 | 30 |
| `w_glasses` | 동그란 안경 | 얼굴 | 50 |
| `w_scarf` | 겨울 목도리 | 목 | 80 |
| `w_bluehat` | 파란 모자 | 머리 | 100 |
| `w_bag` | 탐험 가방 | 등 | 130 |
| `w_crown` | 황금 왕관 | 머리 | 200 |

- 가격 근거 (게임 안에서 직접 센 첫 탐험 최대 코인): 1~4차시 각 93개, 5차시 55 · 6차시 61 · 7차시 65 · 8차시 50, 모두 603개 (+ 스킬 보너스 조금)
  - 리본 30 = 한 지역 절반쯤. 6개 합계 590 = 1~6차시 최대치(488)보다 많아서 한꺼번에 다 살 수는 없어요.
- 저장 (`panda-explorers-v1` 안에 칸 하나 추가, 다른 칸은 그대로)

```js
save.shop = { v: 1, owned: ['w_ribbon', ...], wear: { head: 'w_ribbon', face: null, neck: null, back: null } }
```

- `migrateShop()`: 예전 저장에 칸이 없으면 기본값을 넣고, 이상한 값(모르는 ID·안 산 아이템 장착·부위가 틀린 장착)은 고쳐요. 다른 칸은 건드리지 않아요.
- `buyItem(id)`: ID만 받고 가격은 목록에서 읽어요. 모르는 ID·0 이하·정수가 아닌 가격은 거절, 이미 산 것은 거절, 코인이 모자라면 거절. 통과하면 `save.coins`에서 한 번만 빼고 `owned`에 넣고 저장. `totalEarned`(모은 합계)는 줄지 않아요.
- `equipItem(id)` / `unequipItem(id)`: 산 것만 장착, 부위마다 하나(같은 부위는 자동 교체). 코인 안 들어요.
- 그림: `drawWear(g, x, y, 칸크기, 방향, wear, 'back' | 'front')`. `drawPlayer()`에서 판다 그림 **바로 앞(가방)**과 **바로 뒤(나머지)**에 같은 위치·같은 좌우 뒤집기로 덧그려요. 머리 줄은 서기·걷기·점프가 같아서 위치가 어긋나지 않아요.
- 꾸미기는 그림만 바꿔요. 이동·점프·HP·문제·해금·결과 기록에는 영향이 없고, 선생님 시트로도 보내지 않아요.

## 5. 다음 단계: 판다 방 꾸미기 (설계만, 아직 만들지 않음)

### 데이터 (지금 구조에 그대로 이어 붙이기)

- 아이템: 같은 `SHOP_ITEMS`에 `kind: 'room'`, `spot`(놓는 자리)을 더해요. ID는 `r_`로 시작.

```js
{ id: 'r_bed_bamboo', kind: 'room', spot: 'bed', name: '대나무 침대', price: 120 }
{ id: 'r_rug_star', kind: 'room', spot: 'floor', name: '별 러그', price: 60 }
```

- 자리(정해진 칸에 하나씩): `ROOM_SPOTS = { bed: '침대', desk: '책상', plant: '화분', floor: '바닥(러그)', wall: '벽 장식', shelf: '책장', window: '창문 장식' }`
- 저장: `save.shop.owned`(옷장과 같은 목록) + `save.shop.room = { bed: null, desk: null, ... }` (자리마다 가구 ID 하나)
- `migrateShop()`에 `room` 보완만 더하면 돼요(옷장과 같은 방식: 안 산 것·자리가 틀린 것은 비움).
- 구매는 지금 `buyItem(id)`를 그대로 써요(가격은 목록에서). 배치는 `placeItem(id)` / `clearSpot(spot)`를 새로 만들어요(코인 안 듦).

### 해야 할 일 (다음 요청 때)

1. 가구 7종 픽셀 그림 (침대·책상·화분·러그·벽 장식·책장·창문 장식), 방 배경 그림
2. `SHOP_ITEMS`에 `kind: 'room'` 아이템과 가격 (지금 코인 흐름과 옷장 가격을 보고 결정)
3. `save.shop.room` 보완(`migrateShop`) + `placeItem` / `clearSpot`
4. 방 화면: 방 그림 + 자리 버튼 → 그 자리에 놓을 수 있는 가구 목록 → 미리보기 → 사기 → 놓기 (옷장 창과 같은 흐름)
5. 홈 화면에 「🏠 판다 방」 버튼 (그때 처음 보여 줘요)
6. 테스트: 옷장과 같은 항목(중복 구매·코인 한 번·저장·새로고침) + 자리마다 하나 + 옷장 기록이 그대로인지

## 1. 지금 저장 구조 (localStorage)

- 저장 위치: 브라우저 `localStorage`, 키 `panda-explorers-v1` (JSON 한 덩어리)
- 기기·브라우저마다 따로 저장돼요. 로그인이나 서버가 없어서 **다른 기기와 동기화되지 않아요.**
  - 예: 학교 크롬북에서 모은 코인은 집 태블릿에 없어요.
  - 크롬 시크릿 창, 인터넷 기록 삭제, 저장 공간 정리를 하면 사라져요.

| 칸 | 뜻 | 비고 |
|---|---|---|
| `level`, `exp`, `maxHp` | 레벨 · 경험치 · 최대 HP | |
| `coins` | **지금 가진 코인 (지갑)** | 상점에서 쓰면 줄어듦 |
| `totalEarned` | **지금까지 모은 코인 합계** | 쓰지 않아도 줄지 않음 (이번에 추가) |
| `coinsEver[지역]` | 지역마다 이미 받은 맵 동전 번호 | 새로고침·홈·새 탐험 파밍 방지 (이번에 추가) |
| `dropsEver[지역]` | 지역마다 이미 동전을 준 몬스터 번호 | 같은 이유 (이번에 추가) |
| `correct`, `wrong`, `words` | 맞힌/틀린 수, 낱말별 맞힌 수 | |
| `cards` | 모은 배움 카드 | |
| `clears[지역]` | 지역별 최고 별 수 (0~3) | |
| `helpSeen` | 조작 안내를 봤는지 | |

- 탐험 중인 지도 상태(위치, 잡은 몬스터)는 저장하지 않아요. 새로고침하면 그 지역은 처음부터지만, 이미 받은 동전은 다시 받을 수 없어요.

## 2. 코인이 얼마나 모이나 (실제 숫자)

지도는 세 지역이 같은 배치예요 (`LAYOUT`).

| 출처 | 개수 | 언제 |
|---|---|---|
| 맵 동전 | 47개 (발판 36 + 땅 11) | 지역마다 **처음 한 번만** |
| 몬스터 동전 | 12마리 × 3 = 36개 | 몬스터마다 처음 한 번만 |
| 보스 동전 | 8개 | 처음 한 번만 |
| **지역 하나 첫 탐험** | **약 91개** | |
| **세 지역 모두** | **약 273개** | |
| 다시 탐험·빠른 퀴즈 | 0개 | 연습은 마음껏, 코인은 안 늘어남 |

- 예전 버전(이번 개선 전)을 해 본 기기는 지갑에 이미 코인이 있을 수 있어요. 예전 대나무 언덕은 몬스터마다 3~7개, 연속 정답 보너스 +5가 있었고, 새로고침하면 동전이 다시 생겼어요.
  - 그래서 기기마다 잔액이 대략 0~300개 이상으로 제각각일 거예요.
  - 실제 잔액은 각 기기 브라우저 안에만 있어서 제가 볼 수 없어요.

### 가격 제안

| 아이템 | 가격 | 이유 |
|---|---|---|
| 🧣 빨간 스카프 | **40** | 첫 지역만 해도 살 수 있는 "첫 보상" |
| 🎋 대나무 모자 | **80** | 지역 1개 + 조금 |
| ⭐ 별 안경 | **120** | 지역 2개쯤 |
| **합계** | **240** | 세 지역 합계 273개 안에서 모두 살 수 있음 |

- 다시 하는 탐험에도 작은 동기가 필요하면 이렇게 할 수 있어요 (선택).
  - 클리어 보상: 지역마다 **하루 1번** +5코인
  - 별 3개를 처음 받을 때 +10코인

## 3. 상점 · 꾸미기 설계

### 저장 추가 (버전 그대로, 칸만 추가)

```js
save.owned = { scarf: true }      // 산 아이템
save.equip = { neck: 'scarf', head: null, face: null }   // 부위마다 1개씩 착용
save.buyLog = [{ id: 'scarf', price: 40, at: 1730000000000 }]   // 영수증 (최근 20개)
```

- 지갑과 꾸미기는 **모든 지역이 같이 써요** (지역별로 나누지 않음).

### 이전(마이그레이션)

- `migrateSave()`에서 `owned`, `equip`, `buyLog`가 없으면 빈 값으로 채워요.
- 장착 중인데 `owned`에 없는 아이템은 벗겨요.
- 이번에 이미 쓰고 있는 방식과 같아서, 예전 저장도 오류 없이 열려요.

### 사기 (정확히 빼기 · 두 번 사기 방지)

```js
function buy(id) {
  const it = ITEMS[id];
  if (!it || save.owned[id]) return '이미 있어요';          // 중복 구매 막기
  if (save.coins < it.price) return '코인이 부족해요';
  save.coins -= it.price;                                   // 정확히 가격만큼
  save.owned[id] = true;
  save.buyLog.push({ id, price: it.price, at: Date.now() });
  writeSave();                                              // 한 번에 저장
}
```

- 사기 버튼은 누르는 즉시 잠가요 (빠르게 두 번 눌러도 한 번만 처리).
- **지갑(`coins`)만 줄고 `totalEarned`는 그대로**예요. 기록 화면에는 둘 다 보여 줘요.
- 되팔기는 없음 (파밍 구멍이 생기지 않게).

### 끼우기 / 빼기

- 상점 화면에서 산 아이템을 누르면 끼우고, 한 번 더 누르면 빼요.
- 부위(목·머리·얼굴)마다 하나씩만 끼울 수 있어요.

### 판다 그림에 그리기

- 판다는 32×32(16×16 스프라이트 2배)로 서 있기 / 걷기 1·2 / 점프 네 가지 모양이 있어요.
  - 머리 줄(위 11줄)은 네 모양 모두 같아요 → 모자·안경은 위치 하나로 충분해요.
  - 몸통 첫 줄(빨간 목도리 자리 `r`)도 네 모양 모두 같은 줄 → 스카프는 이 줄 색만 바꾸고 꼬리를 한 칸 그려요.
- 아이템마다 작은 픽셀 조각(16×6 이하)을 만들고, `drawPlayer()`에서 판다를 그린 바로 뒤에 같은 위치·같은 좌우 뒤집기로 덧그려요.
  - 걷기 중 위아래 흔들림(`bob`)과 점프 모양에도 그대로 따라가요.
  - 퀴즈 카드, 시작 화면 프로필 판다에도 같은 함수로 그려요.
- 확인할 것: 걷기·점프·좌우 방향 전환·맞았을 때 깜빡임(`inv`)에서 아이템이 몸과 같이 움직이는지 스크린샷으로 확인.

### 파밍 방지와의 관계

- 코인은 이미 지역·동전·몬스터마다 한 번만 들어와요 (`coinsEver`, `dropsEver`).
- 홈으로 갔다 오기, 새로고침, 처음부터 새 탐험, 빠른 퀴즈로는 늘지 않아요.
- 남는 한계: 기록을 지우면(⚙ 설정 → 확인) 처음부터 다시 모을 수 있어요. 대신 산 아이템도 같이 사라지니 이득이 없어요.

## 4. 지역별 배경음악 (BGM)

### 원칙

- **저작권이 불분명한 음악 파일은 쓰지 않아요.** 지금 효과음처럼 WebAudio로 **코드가 직접 음을 만들어** 짧은 반복곡을 연주해요. 외부 파일이 없어요.
- 나중에 선생님이 직접 만들었거나 사용 허락을 받은 파일이 생기면, 음성 파일(`AUDIO_FILES`)처럼 `BGM_FILES = { forest: 'bgm/forest.mp3' }`에 넣으면 그 파일을 먼저 쓰게 만들어요.

### 지역별 분위기 (테마에 한 칸 추가)

| 테마 | 분위기 | 만드는 법 (예시) |
|---|---|---|
| forest 대나무 언덕 | 잔잔한 숲 | 중국 5음 음계(도레미솔라), 느린 템포 84, 부드러운 삼각파 멜로디 + 낮은 베이스 |
| village 이름 마을 | 밝고 신나는 중국풍 | 5음 음계, 템포 120, 사각파 멜로디 + 통통 튀는 리듬(목탁 느낌 짧은 소음) |
| cave 숫자 계곡 | 신비롭고 리듬감 있게 | 단조 느낌 5음, 템포 100, 메아리(짧은 딜레이) + 똑딱 리듬 |

```js
THEMES.forest.bgm = { tempo: 84, scale: [0, 2, 4, 7, 9], wave: 'triangle', melody: [...], bass: [...] };
```

### 소리 구조

```
효과음(SFX) ─┐
배경음(BGM) ─┼─ 각각 볼륨 노드 ─→ 전체 볼륨 ─→ 스피커
```

- `sfxGain`, `bgmGain`을 따로 둬서 볼륨을 따로 조절해요 (설정에 슬라이더 두 개).
- 설정 저장: `save.audio = { sfx: 0.8, bgm: 0.5, bgmOn: true }`

### 언제 켜고 끄나

| 상황 | BGM |
|---|---|
| 처음 화면 | 꺼짐 (자동 재생 막힘 + 수업 중 조용히) |
| ▶ 탐험 출발을 누른 뒤 | 그 지역 곡 시작 (버튼 누름 = 사용자 동작이라 모바일에서도 재생 가능) |
| 퀴즈가 열리면 | 볼륨을 30%로 낮춤 (덕킹) |
| 🔊 듣기(중국어 음성) 중 | 볼륨을 10%로 낮췄다가 끝나면 원래대로 |
| 🏠 홈으로 이동 | 0.5초 동안 줄이며 멈춤 |
| 다른 지역 시작 | 이전 곡 멈추고 새 곡 |
| 🔊 버튼으로 소리 끔 | BGM·효과음 모두 멈춤 |
| 탭을 다른 데로 옮김 | 잠시 멈춤 (`visibilitychange`) |

### 모바일 주의

- iOS·안드로이드는 사용자가 화면을 누르기 전에는 소리를 못 내요.
  - 그래서 처음 화면에서는 틀지 않고, "탐험 출발" 버튼을 누를 때 `AudioContext.resume()` 후 시작해요.
- 아이폰 무음 스위치가 켜져 있으면 WebAudio 소리가 안 날 수 있어요. 소리 안내 문구에 함께 적어요.
- 저사양 기기를 위해 동시에 나는 음은 3개 이하로 해요.

### 확인 계획

- 자동 테스트로 확인할 수 있는 것:
  - 퀴즈 열면 `bgmGain` 값이 내려가는지
  - 홈으로 가면 멈추는지
